This tutorial provides a comprehensive guide for developers on how to integrate the core functionalities of Morpho Markets: supplying collateral, borrowing, repaying debt, and withdrawing collateral.

Unlike ERC4626 vaults, Morpho Markets have a unique interface defined by the core `Morpho` contract. Understanding these functions is essential for building any application with borrowing capabilities.

Choose API preparation or SDK construction below. The API returns calls for the user's wallet to authorize and send; the [Morpho SDK](/developers/sdks/morpho-sdk/) builds transactions locally.

## Key Concepts: Assets vs. Shares [#key-concepts-assets-vs-shares]

The core accounting system in Morpho Markets revolves around the concepts of `assets` and `shares`. This applies to the `borrow` positions (the loanable asset), but **not** to the collateral.

| Concept    | Functions Affected | Description                                                                                       |
| ---------- | ------------------ | ------------------------------------------------------------------------------------------------- |
| **Assets** | `borrow`, `repay`  | The actual underlying token (e.g., USDC, WETH) that a user wants to lend or borrow.               |
| **Shares** | `borrow`, `repay`  | Internal accounting units representing a proportional claim on the market's total supply or debt. |

**Best Practice:**

* For `borrow`, specifying an exact asset amount is the most common and intuitive approach for users.
* For **full repayments**, choose the full-debt mode shown in the API or SDK tab to avoid leaving a small debt balance.
* Collateral (`supplyCollateral` and `withdrawCollateral`) is always handled in `assets`.

## Prerequisites [#prerequisites]

For the Python examples, install Requests with `pip install requests`.

Before you begin, you will need:

* The `MarketParams` for the market you want to interact with. You can find active markets using the [Read API](/developers/blue/tutorials/get-data/#market-parameters).
* An account with a balance of the collateral asset (e.g., wstETH) and the loan asset (e.g., WETH for repayments).

    | ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
    | `data.status`, `data.action` | Require `prepared` and `blue.borrow`.                                                                                                                                                                                             |
    | `data.simulation.status`     | Require `success`. A failed simulation has no executable calls.                                                                                                                                                                   |
    | `data.calls`                 | Inspect targets, calldata, values, and approvals; preserve order.                                                                                                                                                                 |
    | `data.simulation.effects`    | Compare `supplied_collateral_assets`, `gross_assets`, `referral_fee_assets`, `net_assets`, `ltv_bps`, and `max_ltv_bps` with the user's intent. Inspect `data.simulation.position_changes.collateral_assets` and `borrow_shares`. |

    If `status` is `signature_required`, complete the signature and continuation flow before expecting calls. Do not send an error response or a `simulation_failed` result.

    The user's wallet sends the returned calls, in order, only after checking the simulation and [verifying the signed proof](/api/actions/verify-responses/), with user approval. Morpho does not submit transactions.

    For collateral-only supply, use [Supply collateral (only)](#supply-collateral-only). For borrow only, omit both `collateral_amount` and `funding`. Do not concatenate independently prepared call lists and assume atomicity.

    **Optional borrow referral fee**

    The borrow route accepts an optional `referral_fee` object:

    ```json
    {
      "bps": 25,
      "recipient": "0x1111111111111111111111111111111111111111"
    }
    ```

    The integrator chooses the nonzero recipient; replace the placeholder address above. There is no default recipient. `bps` is an integer from 1 to 200. Omit the entire object for no fee rather than sending zero. The recipient receives loan tokens deducted from the gross borrowed amount: debt is unchanged while the wallet receives less. Compare `gross_assets`, `referral_fee_assets`, and `net_assets` in the simulation. The standalone collateral-supply route does not support this fee.

    import { parseUnits } from "viem";
    import { MarketParams } from "@morpho-org/morpho-sdk/entities";

    const market = client.morpho.blue(
      new MarketParams({
        loanToken: "0xLoanToken...",
        collateralToken: "0xCollateralToken...",
        oracle: "0xOracle...",
        irm: "0xIrm...",
        lltv: 860000000000000000n, // 86%
      }),
      mainnet.id,
    );

    The SDK builds an atomic BlueBundlesV1 call that supplies collateral, then borrows, with an LLTV buffer that prevents the new position from being instantly liquidatable. `getRequirements()` returns the ERC-20 approval (or ERC-2612 permit signature) for the collateral token, plus the one-time `morpho.setAuthorization(blueBundlesV1, true)` if it has not been done yet.

    ```typescript
    const positionData = await market.getPositionData(account.address);

    const supplyCollateralBorrow = market.supplyCollateralBorrow({
      collateralAssets: parseUnits("1.0", 18), // 1 wstETH
      borrowAssets: parseUnits("2000", 18),    // 2000 WETH
      userAddress: account.address,
      positionData,
      deadline: BigInt(Math.floor(Date.now() / 1000) + 3_600), // Unix seconds, now + 1 hour
    });

    const signatures = [];
    for (const req of await supplyCollateralBorrow.getRequirements()) {
      if ("sign" in req) {
        signatures.push(await req.sign(client, account.address));
      } else {
        await client.sendTransaction(req); // approval / setAuthorization
      }
    }

    const txHash = await client.sendTransaction(supplyCollateralBorrow.buildTx(signatures));
    console.log("Supply + borrow:", txHash);
    ```

    Repayment requires an existing debt position; otherwise the API returns `422 POSITION_EMPTY`.

    **Optional repayment referral fee**

    The repayment route supports the same optional `referral_fee` object shown in the borrow tab: integer `bps` from 1 to 200 and a nonzero `recipient` chosen by the integrator. Omit it for no fee. The fee is added on top of loan assets actually repaid, not deducted from the debt repayment. Compare `repaid_assets` plus `referral_fee_assets` with the wallet's total loan-token spend. The standalone collateral-withdrawal route does not support this fee.

    For full repayments, pass `maxUint256` as the shares-mode repay input (`repayShares`): the contract replaces it with the position's live borrow shares, so the full debt is cleared regardless of interest accrued between quote and inclusion (no dust). Passing the position's freshly fetched `borrowShares` also works when the data is fresh. The operation order is encoded for you: repay first, then withdraw.

    ```typescript
    import { maxUint256, parseUnits } from "viem";
    import { MarketParams } from "@morpho-org/morpho-sdk/entities";

    const market = client.morpho.blue(
      new MarketParams({
        loanToken: "0xLoanToken...",
        collateralToken: "0xCollateralToken...",
        oracle: "0xOracle...",
        irm: "0xIrm...",
        lltv: 860000000000000000n, // 86%
      }),
      mainnet.id,
    );

    const fresh = await market.getPositionData(account.address);

    const repayWithdrawCollateral = market.repayWithdrawCollateral({
      repayShares: maxUint256,                   // full repay (saturated close; use { repayAssets } for partial)
      collateralAssets: parseUnits("1.0", 18),   // 1 wstETH
      userAddress: account.address,
      positionData: fresh,
      deadline: BigInt(Math.floor(Date.now() / 1000) + 3_600),
    });

    const signatures = [];
    for (const req of await repayWithdrawCollateral.getRequirements()) {
      if ("sign" in req) {
        signatures.push(await req.sign(client, account.address));
      } else {
        await client.sendTransaction(req); // loan-token approval / setAuthorization
      }
    }

    const txHash = await client.sendTransaction(repayWithdrawCollateral.buildTx(signatures));
    console.log("Repay + withdraw:", txHash);
    ```

        		panic(fmt.Sprintf("Action request failed (HTTP %d): %s", response.StatusCode, data))
        	}
        	fmt.Println(response.StatusCode)
        	fmt.Println(response.Header.Get("Morpho-Action-Proof"))
        	fmt.Println(string(data))
        }

    If `status` is `signature_required`, complete the signature and continuation flow before expecting calls. Do not send an error response or a `simulation_failed` result.
